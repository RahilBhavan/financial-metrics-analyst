# Use the analyst directly in T3

Open this repository in T3 and ask a financial question, for example:

> What was Microsoft's FY2026 gross margin? Show the filing.

The project instructions in `AGENTS.md` route financial questions to `.agents/skills/financial-metrics/SKILL.md`. If your chosen provider does not automatically load project instructions, start with:

> Read `.agents/skills/financial-metrics/SKILL.md` and use that workflow to answer my financial questions.

T3's current model interprets your question and calls the local Python CLI. There is no separate model API key, project MCP server, MCP configuration or Python dependency install. Model usage follows the provider account you already use in T3; this does not promise unlimited or free provider usage.

## How answers are checked

- `python3 -B -m financial_metrics.t3 scope` lists the reviewed issuer-specific years/quarters and metrics.
- `python3 -B -m financial_metrics.t3 tools` lists the seven validated local tools and input schemas.
- `python3 -B -m financial_metrics.t3 call` accepts a tool name and arguments as JSON on stdin. Its output includes the result and selectable evidence IDs. `--index N` numbers that call for the final ordered list.
- `python3 -B -m financial_metrics.t3 answer` accepts an ordered `calls` list and `evidence` IDs. It reruns the calls against the local service, validates the results, renders the selected records and traces every number. Saved result values and model-written financial prose are rejected.

The Python path is entirely in-process and uses the same contracts, exact arithmetic, source selection and evidence renderer as the optional MCP adapter. It launches no model or MCP subprocess. It makes no network calls and does not write to snapshots.

A final request looks like this:

```sh
python3 -B -m financial_metrics.t3 answer --text <<'JSON'
{"calls":[{"name":"get_coins_per_share","arguments":{"firm":"MSTR","week_end":"2026-09-30"}}],"evidence":["c0.week.net_mnav"]}
JSON
```

Evidence IDs bind a company, metric, period, signed value and filing source. Every `answer` execution reads actual local data again, so editing an inspected result cannot insert a fabricated value. This is an answer-verification boundary, not a sandbox for the T3 host agent: T3's own permissions still govern its other tools. Source correctness rests on the independent filing checks, not on the host model's opinion.

For SEC requests, resolve the company first and use the cached `lookup_timestamp` date as the latest permitted `as_of`, unless you asked for an earlier filing cutoff. Annual and standalone quarterly cash flows include operating, investing and financing totals and cash capital expenditures. Use `get_quarterly_facts` for quarterly cash flows, capex and free cash flow; use `calculate_metrics` for annual free cash flow. Free cash flow is operating cash flow minus cash capital expenditures. Quarterly totals derive from current YTD minus the preceding quarter YTD, with both sources retained. Forecasts remain unsupported. Missing metrics are unavailable, never silently zero.

## Verification and compatibility

`python3 -B scripts/verify_t3.py --questions` prints the integration questions. A T3-hosted model selects requests using the skill; `--requests <json-file>` reruns and scores the actual calls and selected fields against the source-backed expectations. `reports/t3-smoke.json` holds the live T3 integration receipt. Unit tests also deny network and subprocess events and remove model keys while exercising the direct path.

The existing MCP server remains an optional interface for other hosts. The optional Claude CLI and Messages API adapters remain for compatibility and historical evaluations. Their setup and key requirements do not apply to T3-native use. The old Messages API smoke is a record of an optional adapter that was not exercised, not a prerequisite for this workflow.

The current scope has twelve issuers (adding AMD and INTC) and six reviewed 10-Q quarters per issuer. Capital-spending scope follows the reviewed standard tag: Intel excludes property additions classified as financing cash flows; NVIDIA includes intangibles, Visa includes technology, Robinhood excludes separately reported capitalized software, and AMD excludes discontinued-operation capex while operating cash flow is consolidated. These differences appear in answer warnings. Recent Coinbase capex and free cash flow remain unavailable because the standard capex tag is absent; no missing payment is assumed to be zero.
