# Design system: financial metrics analyst cards

This file is the design system for the public cards of this repository (the Eval Log series on X). It applies to images in `docs/images/` and to nothing else. `scripts/render_ambiguity_card.py` is the implementation and the check; this file is the specification it follows.

## Status

Added for coding request `cr-4f15a647`, which Grok Bot filed and Rahil approved for implementation. The request fixes the values below. They differ from the shared public bundle `rahil-design@3.3.1` (charcoal, white and yellow, Anton and IBM Plex Sans, 1200×675 and 1080×1080 canvases). No current decision by Rahil that moves the Eval Log cards off the shared bundle has been found, so the cards count as **design review pending** until Rahil confirms this file as the governing system for them. Merging or CI passing does not confirm it.

## Palette

Navy is the base. Red marks the one thing the title names and nothing else.

| Role | Hex | Use |
| --- | --- | --- |
| Navy | `#0B1F4B` | Canvas, bars, ink on paper |
| Paper | `#F5F5EF` | Title and bar-value text on navy, figure panel |
| Top | `#C9D1DE` | Kicker and footer text on navy |
| Muted | `#44506A` | Labels on the paper panel |
| Red | `#C8102E` | The single highlighted series, on the paper panel only |

Contrast: red on paper is 5.4:1, muted on paper 7.4:1, top on navy 10.4:1, paper on navy 14.6:1. Red never sits on navy (2.7:1). Never add a second accent, a gradient or a shadow.

## Type

- Titles: Roboto Slab Bold (700).
- Everything else: Archivo Regular (400) and SemiBold (600).
- **Every text element is at least 26px at 1024px wide**, including the kicker, labels, bar values and footer. The renderer measures the computed size of every text node and fails below 26px.
- Fonts are embedded from `scripts/card-fonts/` (Roboto Slab: Apache-2.0; Archivo: SIL OFL, licenses alongside). No system font may substitute: the renderer fails unless exactly these two families render.
- Sizes used: title 46px (landscape) and 60px (square); bar values 34px and 44px; highlight line 30px and 34px; labels and footer 26px.

## Canvases

Two formats from one script, 1024px wide in both:

- Landscape 1024×640, padding 36px.
- Square 1024×1024, padding 48px.

Both carry the same content in the same order: kicker, title, figure panel, footer. Nothing is cropped or hidden to fit; shorten the copy instead.

## Title states the takeaway

The title is a sentence that says what the reader should conclude, not a topic. "Microsoft “profit” has two answers, so it asks which" passes; "Microsoft FY2026 profit" does not. It is at most two lines. When the title names a result, the highlight marks that result.

## Figure

- One panel on paper with 12px corners. Bars start at zero and share one scale (Lie Factor 1); the renderer checks the rendered bar widths against the data ratio.
- Values sit inside the bar end in Archivo SemiBold, so no legend or gridline is needed.
- Red appears once: a rule and a line of text that name what the title says. A bar may be red instead when the title names that bar's value; never both, and never an arbitrary bar.
- Small sets stay as bars or a table. No 3D, no decoration, no pie.

## Footer: source and date

Two lines in Archivo 26px on navy, at the bottom of the card:

1. `Source:` the filing, with the period it covers.
2. The accession number, then the date of the data (`SEC data as of`), taken from the snapshot manifest, not from the clock.

The footer states both the period and the observation date because they differ.

## Numbers come from data

Card values are read from `data/<issuer>/ground-truth.json` and the date from `data/<issuer>/manifest.json`. Never type a figure into the renderer. The renderer checks that each figure shown equals the formatted source value.

## Alt text

`docs/images/ambiguity-alt.txt` is generated by the same script from the same values as the card, so it cannot disagree with it. It names the chart type, both values with units, the period, the highlighted message and the source with its date. A test compares the alt text with the ground truth.

## Hashes and handoff

The script writes `docs/images/ambiguity-manifest.json` with the SHA-256, width and height of each PNG. A test checks the committed PNGs against it. A Content Package takes the PNGs from `docs/images/` byte for byte; its recorded SHA-256 must equal the manifest. Re-render only with `python3 -B scripts/render_ambiguity_card.py` (needs Chromium) and commit the PNGs, alt text and manifest together.

## Review before use

Passing the renderer's checks is not design approval. Before a card is posted: inspect both PNGs at feed size (about 356px wide on a phone), check the title against the post text, and confirm the governing design system with Rahil. At feed size 26px text renders at about 9px; that is the cost of the fixed 1024px spec and is below the 18px feed floor in `rahil-design@3.3.1`.

## Don't

- Don't change a figure, the source or the date without changing the data it comes from.
- Don't use a font other than the two above, or text under 26px.
- Don't add a second highlight colour or color a bar to decorate.
- Don't use internal tool vocabulary on the card (status codes, function names).
